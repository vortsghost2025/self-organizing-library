# WE Framework Lineage

This file records conceptual lineage without rewriting historical artifacts.

## Phase 1 — Rosetta Stone

Papers A-E established the early WE4FREE claim family around symmetry, invariants, constrained selection, propagation, recovery, and cross-domain translation. The original work explicitly left compositionality, reversibility, locality, higher-category structure, and quantitative invariants as open questions.

## Phase 2 — Paper F / Book 6

Implementation failures forced the theory to become self-correcting:

```text
failure -> detection -> correction -> constraint refinement -> new stable state
```

Named Failure Modes turned implementation defects into a research corpus about missing or mis-specified constraints, observability limits, authority boundaries, temporal validity, schema/behavior mismatch, delegation, and trust infrastructure.

## Phase 3 — Long-running WE state machinery

Archivist, Library, Swarm, Control Plane, and compact/restore workflows supplied implementation experience with:

- finite model context;
- durable external state;
- synchronized partial projections;
- compact operational representations;
- restoration after context turnover;
- reconstruction after interruption;
- authority-scoped reconciliation.

Book 7 formalizes this as phenotype-preserving state compression and effective temporal context rather than native context-window expansion.

## Phase 4 — External adversarial testing

AIDE External-Run Veritas / Obscura provided an independent architecture on which authorization, binding, freshness, provenance, replay, trust divergence, and causal semantics could be attacked.

This phase is evidence for or against specific WE Framework hypotheses under frozen mappings. It does not transfer ownership of the parent theory to the external project.

## Phase 5 — Rosetta Calculus

Book 7 attempts to combine:

- quotient-style phenotype classes;
- compact / restore fidelity;
- belief-state lattices;
- ambient constraint lattices;
- semantic binding;
- causal slices;
- failure-preserving and recovery-preserving translations;
- prospective cross-domain failure prediction.

## Attribution principle

Conceptual lineage and code authorship are separate questions.

The WE Framework can originate a research question while an external repository supplies the implementation under test. External code, architecture, terminology, and authorship remain credited to their original project. WE results must state which part is theory, which part is bridge logic, and which part is observed behavior of the external system.
